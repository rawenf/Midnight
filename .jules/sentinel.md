## 2026-05-13 - [HIGH] Stored XSS via User-Provided URLs in React `href`
**Vulnerability:** A Stored Cross-Site Scripting (XSS) vulnerability was found in `src/components/PinDetailView.tsx`. The `pin.source` field (which is user-controllable from Firestore) was being passed directly to the `href` attribute of an anchor tag (`<a href={pin.source || "#"}>`). An attacker could supply a `javascript:` URI, which React does not sanitize, leading to arbitrary JavaScript execution when the link is clicked.
**Learning:** React protects against XSS in text content (via `{data}`) by escaping it, but it *does not* sanitize or validate `href` attributes. A malicious user can input `javascript:alert('XSS')` into a URL field, bypassing normal React XSS protections.
**Prevention:** Always validate and sanitize user-provided URLs before using them in `href` attributes. A common pattern is to ensure the URL starts with `http://` or `https://`. For example: `href={url.startsWith('http') ? url : '#'}`. Also, always include `target="_blank"` and `rel="noopener noreferrer"` for external links to prevent window object leakage.
